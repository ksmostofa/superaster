# Launch workflow evidence

Checked 2026-10-08 JST against active specification revision 1.1. This is prerequisite research for G1, not a gate result. All file examples below are proposed acceptance inputs and outputs, not measured processing results.

## Decision and limits

Build removal first, then exact preparation, corrections, batches, adapters and destinations in gate order. These ten priorities are an evidence-weighted product decision. They are not a measured global usage ranking. Exact completed-edit counts and per-person frequency are unknown for every workflow here. Shared audience evidence cannot distinguish the order of closely related tasks.

The strongest available evidence is broad removal and utility interest, followed by repeated seller work and social design creation. Official-photo preparation has costly rejection risks but weaker volume evidence. Developer automation, physical printing and cutout repair have concrete requests and dependency value; available sources do not quantify their demand. No interview, user telemetry or controlled time-saving study was conducted for Superaster.

## UI states and expected evidence

| State | Required user action and feedback | Desktop/mobile inspection target |
| --- | --- | --- |
| Input | Select/drop one file or batch; clearly show supported bounds and preserved source. | Image/action dominate; reachable file control and drag-over focus; no hover-only action. |
| Model preparation | Explicit approved profile/download, true bytes/progress, cancel and setup/recovery. | Distinguish download from initialization and processing; phone text does not clip. |
| Processing | Stage progress based on real pipeline, safe cancellation, responsive controls. | No simulated percentage; status/error live announcements; reduced motion. |
| Result | Original/cutout comparison, transparent/light/dark composites, true output dimensions. | Inspect image at useful size; touch and keyboard compare. |
| Correction | Erase/restore brush, exact undo/redo, current mask change. | Brush works without page scrolling; visible selected mode, focus and touch target. |
| Export | Supported format, canvas/byte constraints, actual file and execution record. | Download controls remain reachable and do not conceal image. |
| Error | Specific failing file/stage/profile, recoverable action or retake guidance. | Error survives panel changes; no successful no-op. |
| Batch | Item status, completed-file downloads, cancel, explicit retry/resume, manifest. | Long filenames/wrapped progress do not overflow; completed work stays accessible. |

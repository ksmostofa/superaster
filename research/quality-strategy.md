## Implementation versus model evidence

| Suspected cause | Reviewed behavior | Conclusion |
| --- | --- | --- |
| Wrong input normalization or layout | Shared `modelInput` writes NCHW RGB. BiRefNet uses 1/255 and ImageNet mean/std; BEN2 uses RGB 0..1. Both adapters resize to the model's declared square dimensions and check actual tensor names, dtype and shape. | These declared semantics match inspected source. No demonstrated normalization or stale-512 defect. |
| Wrong output activation or dtype | BiRefNet terminal Conv/Cast emits FLOAT logits and receives one external sigmoid. BEN2 has terminal sigmoid coverage and receives none. The actual CPU observer returned `Float32Array` input and `Float16Array` output for BEN2. The decoder handles numeric Float16Array values and raw Uint16Array half bits separately. | No demonstrated second-sigmoid or half-decoding defect. [Actual BEN2 tensor evidence](../evidence/benchmarks/ben2-targeted-df81e4a/runtime-types.json) supports this conclusion. |
| Refinement erased subjects | Both targeted recipes use `edge_cleanup: none`; execution records declare `refinement: none`. | These failures precede edge RGB cleanup. Adjusting that cleanup cannot restore erased alpha. |
| Reused previous image alpha | Native alpha cache identity contains pinned model SHA, raster dimensions and raster byte hash. Both distinct images execute actual inference and have different output hashes. | The reviewed implementation provides no evidence of a stale-alpha cache explanation. |
| Geometry or export erased subjects | Float coverage is interpolated to original dimensions with a bounded half-pixel bilinear mapping, then multiplied by original alpha. RGB is preserved. Exported dimensions and opaque-RGB checks pass. | No demonstrated crop, resize-bound or RGB-encoder cause. All-zero encoded alpha does not prove all continuous model values were exactly zero. |

The [pinned BiRefNet processor](https://huggingface.co/onnx-community/BiRefNet-ONNX/blob/534d3c82d3bb8b2f0867db6dfbc3a525b8e42f67/preprocessor_config.json) and [conversion example](https://huggingface.co/onnx-community/BiRefNet-ONNX/blob/534d3c82d3bb8b2f0867db6dfbc3a525b8e42f67/README.md) support the BiRefNet input/logit contract. Local source bytes and hashes are retained in the [Full1024 source index](../evidence/reviews/full1024-audit/source-index.json); the web tool could not open the processor page, so its inspected local immutable copy supplies that evidence. The [official BEN2 script](https://huggingface.co/PramaLLC/BEN2/blob/e48a20765fb421d19dcdb0bf3cc61e802ca5ec8f/onnx_run.py) supports unit normalization. It also swaps width/height in interpolation and applies per-image min/max scaling, with division by zero for constant output. Superaster intentionally does neither. Copying those source gaps is not a quality fix.

Some numerical equivalence is unproved. Sharp/libvips linear input resizing is not established as byte-identical to the pinned Python/Pillow or Transformers.js processor. The upstream BiRefNet example quantizes alpha before its final image resize, whereas Superaster retains float coverage until final raster assignment. Conversion parity with immutable original weights, raw logits and fp16-versus-fp32 numerical differences have not been measured on these failed cases. A complete source-reference comparison would need the actual source weight revision and a reproducible export; the Full1024 conversion does not provide either. These gaps prevent a causal claim that the model alone is defective.

The source [BiRefNet model zoo](https://github.com/ZhengPeng7/BiRefNet/blob/ebcc0bc8ec7fe919cec829f2dea656b3078acddc/README.md) distinguishes DIS, general segmentation, general matting and portrait checkpoints. Source config inspected in the audit selects DIS5K and a large Swin backbone; the conversion does not name immutable original weights. Consequently, attributing these ONNX bytes to a particular training set or today's general checkpoint is unsupported. Model selection of dominant nearer people and weak separation in crowded vegetation are plausible domain failures, inferred from the observed scenes and task families. They are hypotheses, not established mechanisms or excuses to pass T01.

## The finite next experiment

Use the already downloaded [Full1024 audited artifact](../evidence/reviews/full1024-audit.md), revision `534d3c82d3bb8b2f0867db6dfbc3a525b8e42f67`, 489,666,272 bytes, SHA-256 `3654c741eb80bd926ada8fed1713b506ccf8d30eb1f6487e87eb9f234f33df09`. MIT rights and graph parsing pass. Actual CPU operator execution, resource use and quality remain unproved. Keep it explicit and experimental; keep Auto Quality/Fast unchanged.

1. Preflight the unchanged two-case manifest, evaluation inputs and preserved originals. Let the production loader verify the complete model hash and actual FLOAT `[1,3,1024,1024]` input/FLOAT `[1,1,1024,1024]` output contract.
2. Run one native CPU session, group then fern, with existing normalization, sigmoid, linear input resize, continuous alpha and `edge_cleanup: none`. Record the first initialization and distinct warm-image conditions. Do not change inputs, thresholds, operation settings or the execution provider during this job.
3. Use a delegating observer to record returned dtype, constructor, dimensions, finite raw-logit min/max and continuous-alpha min/max. Record how many alpha values exceed `0.5/255`, the existing nearest-byte PNG boundary. This is a diagnostic of where loss occurs, not a new quality threshold. Never substitute tensor contents. Disclose observer overhead; these measurements do not set performance budgets.
4. Save actual alpha, cutouts and white/black/color composites. Check original preservation and exported pixels. Review the existing all-three-person and foreground-frond expectations. Leave uncertain fine edges `needs_review`; retain `FAIL` for an erased intended person or empty fern. Human hidden-label review remains NOT RUN until performed.

Full1024 supplies four times Full512's input pixels and a full-capacity graph rather than another Lite1024 execution. It tests a useful artifact choice, not a controlled resolution-only experiment. If either named hard failure persists, stop broad screening of this candidate and retain its failure/runtime records. An initialization/resource error is also a result; do not repeat it without a diagnosed cause. If both subjects remain in assistant triage, a separately scoped full screening may be considered. Two cases cannot qualify the default or justify a release claim.
